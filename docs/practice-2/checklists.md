# Чек-листы периферийных сервисов

Отмечать после прогона. Критические проверки перечислены по убыванию риска.

## Gateway

Источник: [ТЗ](../../tz/02-gateway.md).

### Дымовое тестирование

- [ ] `:8080/health` отвечает 200; статусы зависимостей доступны.
- [ ] `/docs` открывается; валидная транзакция получает ответ.

### Критический путь

- [ ] Валидный запрос доходит до Switch; одобрение и отказ возвращаются без искажений.
- [ ] Невалидные поля и отсутствие обязательных полей дают 400 до передачи в Switch.
- [ ] Недоступный downstream даёт 503 с указанием сервиса.
- [ ] Запросы карт, поиска, симуляторов и Dashboard проксируются по назначению; `X-Request-Id` доступен для трассировки.

## Switch

Источник: [ТЗ](../../tz/03-switch.md).

### Дымовое тестирование

- [ ] `:8082/health` отвечает 200; Authorization доступен.
- [ ] `/api/internal/route` обрабатывает запрос с известным BIN.

### Критический путь

- [ ] Отсутствие publisher confirm после одобрения вызывает откат резерва и `DECLINED/96`.
- [ ] Одобренная транзакция публикуется в RabbitMQ с подтверждением до ответа клиенту.
- [ ] Известный BIN определяет правильный issuerId; неизвестный даёт `14` без резервирования.
- [ ] Недоступный Authorization: три попытки, затем отказ `05`.
- [ ] В журнал передаются исходный MTI, сумма, RRN и результат авторизации без искажений.

## Terminal Simulator

Источник: [ТЗ](../../tz/06-terminal-simulator.md).

### Дымовое тестирование

- [ ] `:8085/health` отвечает 200.
- [ ] `/api/simulator/terminal/run` завершает короткий `normal`-прогон и возвращает статистику.

### Критический путь

- [ ] Карты берутся из CMS; транзакции отправляются через Gateway; статистика соответствует ответам.
- [ ] `normal`, `mixed`, `high_value`, `night_time` соблюдают заданные классы карт, сумм и времени.
- [ ] `declines_test` включает неизвестный PAN, BLOCKED, нехватку средств, превышение лимита и успешную покупку.
- [ ] STAN имеет шесть цифр, увеличивается последовательно и циклически переходит после `999999`.

## Merchant / Acquirer Simulator

Источник: [ТЗ](../../tz/07-merchant-acquirer.md).

### Дымовое тестирование

- [ ] `:8084/health` отвечает 200; загружено не менее 20 мерчантов.
- [ ] `/api/simulator/merchant/run` завершает короткий `grocery`-прогон.

### Критический путь

- [ ] Комиссия рассчитана в копейках по ставке мерчанта и сохранена в журнале.
- [ ] `grocery`, `electronics`, `restaurant`, `travel` используют заданные MCC, суммы и время.
- [ ] Явные `mccCodes` переопределяют MCC сценария, сохраняя его распределение сумм и времени.
- [ ] Gateway получает правильные merchantId и acquirerId; комиссия не включается в AuthorizationRequest.
- [ ] Итоги approved/declined соответствуют полученным ответам.

## Transaction Logger

Источник: [ТЗ](../../tz/08-transaction-logger.md).

### Дымовое тестирование

- [ ] `:8088/health` отвечает 200; поиск и статистика доступны.
- [ ] `/ws/transactions` принимает соединение.

### Критический путь

- [ ] Транзакции из RabbitMQ сохраняются с исходными суммой, RRN и результатом.
- [ ] REST-приём создаёт запись с 201; повтор того же id возвращает 200 без дубликата.
- [ ] Поиск сочетает фильтры через AND; пустая выборка, пагинация и total корректны.
- [ ] Статистика соответствует сохранённым данным; recent возвращает последние записи первыми.
- [ ] Новая сохранённая транзакция приходит всем подключённым WebSocket-клиентам.

## Web Dashboard

Источник: [ТЗ](../../tz/09-web-dashboard.md).

### Дымовое тестирование

- [ ] `:3000` открывается; KPI, графики и таблица загружаются.
- [ ] WebSocket подключён; индикатор соединения активен.

### Критический путь

- [ ] Суммы переведены из копеек в рубли; статусы и KPI соответствуют данным Logger.
- [ ] Новая транзакция обновляет таблицу, KPI и графики без перезагрузки.
- [ ] Фильтры статуса, дат, BIN/эмитента и MCC корректно ограничивают выборку.
- [ ] Детали относятся к выбранной транзакции; PAN замаскирован.
- [ ] После обрыва WebSocket индикатор меняется; соединение автоматически восстанавливается.

## Bin Lookup

Источники: [ТЗ интеграции](../../tz/04-authorization.md), [API сервиса](../../services/bin-lookup/README.md).

### Дымовое тестирование

- [ ] `:8096/actuator/health` отвечает 200; известный BIN возвращает данные эмитента.

### Критический путь

- [ ] BIN `400000`–`400004` соответствуют правильным issuerId; неизвестный BIN даёт 404.
- [ ] При 5xx выполняются предусмотренные повторы; при недоступности или таймауте используется issuerId из Switch.

## Notification Service

Источники: [ТЗ событий](../../tz/05-card-management.md), [API сервиса](../../services/notification-service/README.md).

### Дымовое тестирование

- [ ] `:8097/actuator/health` отвечает 200; `/api/notifications` возвращает список.

### Критический путь

- [ ] События создания, изменения и удаления карты доходят через Outbox → RabbitMQ до Notification Service.
- [ ] Полученные события сохраняют тип, routing key и данные исходного события.
- [ ] Список уведомлений и пагинация соответствуют сохранённым событиям.
