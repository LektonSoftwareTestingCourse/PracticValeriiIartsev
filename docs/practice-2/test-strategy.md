## 1. Цель тестирования

- Проверить полный путь покупки: запрос → авторизация → резервирование → журнал → Dashboard.
- Проверить одобрение и причины отказа по статусу, сроку, лимитам и балансу (+ разные терминалы и mcc).
- Исключить ошибочное и повторное списание, изменение баланса и usage при отказе.

## 2. Объект тестирования

- Authorization — решение по транзакции, порядок проверок, учёт лимитов.
- Card Management — создание и изменение карт, генерация PAN, резервирование.
- Остальная СМП — Gateway, Switch, Bin Lookup, симуляторы, Transaction Logger, Notification Service, Dashboard.

## 3. Уровни тестирования

- Модульный — изолированная проверка бизнес-правил и границ.
- API и интеграционный — контракты, взаимодействие сервисов, БД и ошибки зависимостей.
- E2E — покупка и отказы через полную процессинговую цепочку.

## 4. Область тестирования

- Authorization и Card Management: классы эквивалентности, граничные значения, PICT и отдельные проверки приоритета отказов.
- Остальные сервисы: чек-листы smoke и критического пути.
- Нагрузочное тестирование исключено: будет выполняться отдельно.
- Тестирование безопасности исключено: проверяется отдельно СИБами.

## 5. Подход к организации
Риск-ориентированный. Сначала хорошо проверяем core -  Auth. service и Card Managment
Далее проверяем остальные сервисы - чек-лист: smoke тестирование + проверка работы крит. сценариевы
