# Практика 4 — unit-тесты СМП

## Что проверяем

| Сервис | Тестовые классы | Поведение |
|---|---|---|
| Gateway | `TransactionRequestValidatorTest`, `TransactionValidationFilterTest` | Обязательные поля, формат PAN/STAN/MCC/валюты, суммы −1/0/1/2; отклонение плохого JSON, передача исходного тела дальше, обход фильтра для других маршрутов |
| Switch | `RoutingServiceTest`, `RouteServiceTest` | Маршруты BIN, нормализация идентификаторов, передача полей в Logger, недоступность Authorization; компенсация APPROVED при сбое логирования, отсутствие компенсации DECLINED |
| Switch | `AuthorizationClientTest`, `MerchantAcquirerClientTest`, `LoggerClientTest` | Обработка допустимых/пустых/ошибочных ответов, retry без ожидания, открытый circuit breaker, деградация комиссии, команда публикации и AmqpException |
| Authorization | `AuthServiceImplTest`, `AuthorizationRequestTest` | Статус, срок, баланс, результаты обновления лимитов, pairwise-комбинации, ошибки CMS/БД, конфликт обновления лимитов, reserve/rollback, уникальность RRN на границе блока |
| Card Management | `CardServiceImplTest`, `CardTest`, `ReservationTest` | Создание, PATCH, удаление, пагинация, резервирование относительно баланса, запрет повторного reserve и rollback уже отменённого резерва, сохранение полей модели |
| Card Management | `CreateCardRequestTest`, `CardGeneratorServiceTest`, `LuhnValidatorTest`, `CardExpiryDateMapperTest` | Ограничения DTO, параметры и границы генерации, распределение BIN/статусов, Luhn, формат срока |
| Card Management | `OutboxEventProcessorImplTest` | Успешная публикация, PENDING при первых ошибках, FAILED на третьей попытке, сохранение счётчика и ошибки |

Проверяемые классы создаются явно. Репозитории, HTTP-клиенты и RabbitTemplate
заменяются моками. Gateway-фильтр вызывается с `MockServerWebExchange` и моковой
цепочкой; HTTP-сервер и Spring-контекст не запускаются. HTTP-адаптеры Switch
проверяются через моки RestClient, без сетевых соединений.

## Известные расхождения: `@Disabled`

Отключены только проверки требований, которые не выполняет текущее приложение.
В аннотациях указаны ID и причины; ожидаемые результаты требований сохранены.

| Кейсы | Ожидается | Реализация |
|---|---|---|
| A-18 | 05 / ISSUER_TIMEOUT при недоступном CMS | 96 / SERVICE_UNAVAILABLE |
| A-19 | Прямая авторизация суммы 0 отклонена до reserve | AuthServiceImpl одобряет; положительность проверяет Gateway |
| P-14, P-20 | Лимиты имеют приоритет над недостаточным балансом: 61 | Баланс проверяется раньше: 51 |
| CP-01 | Подстановка 15000000 / 300000000 / 100000000 | В createCard передаются null |
| CP-07, CP-09, CP-15 | Отклонение имени длиннее 255 символов | В DTO нет ограничения длины; оно есть в схеме БД |

Причины подтверждены отдельным запуском этих методов с принудительно включёнными
Disabled-проверками: 7 выполнений тестов завершились ожидаемыми
assertion failures, ошибок выполнения нет. Обычный запуск оставляет пять методов
отключёнными; JUnit считает отключённый параметризованный метод одним пропуском.
